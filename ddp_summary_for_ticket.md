# DDP и оптимизация RAM — зачем это нужно

## Проблема

Обучение ансамбля из 64 моделей на больших датасетах (например, Peru — 7 ГБ сжатых данных, сотни ГБ распакованных) требует огромного количества оперативной памяти. Без оптимизации каждый GPU-процесс загружает полную копию данных независимо, что при 4 GPU приводит к ~800 ГБ RAM и OOM-крашам.

Кроме того, обучение 64 моделей последовательно на одном GPU занимает слишком много времени.

## Что сделано

### 1. DDP (Distributed Data Parallel)

Позволяет обучать все 64 модели **одновременно на нескольких GPU**, а не по очереди на одном. Train-данные распределяются между GPU — каждый GPU обучает на своей части данных, а градиенты синхронизируются между ними.

**Результат:** обучение в N раз быстрее при использовании N GPU.

### 2. Оптимизация RAM

Без оптимизации каждый из N GPU-процессов загружал полную копию датасета в свою память, что давало N-кратный перерасход.

Основные меры:
- **Memory-mapped файлы** — данные остаются на диске и подгружаются по требованию, все процессы делят один OS page cache вместо независимых копий
- **Шардирование train-данных** — каждый GPU держит в памяти только свою 1/N часть train-данных
- **Оптимизация препроцессинга** — трансформация численных признаков (noisy-quantile) выполняется порционно без создания промежуточных копий в float64
- **Кэширование** — подготовленный датасет сохраняется один раз и переиспользуется между запусками; при DDP кэш строит только один процесс, остальные ждут

**Результат:** пиковое потребление RAM снижено с ~800 ГБ до ~100-150 ГБ (в зависимости от размера датасета и числа GPU).

## Итог

Совместно DDP и оптимизация RAM позволяют:
- Обучать ансамбли из 64 моделей на 4 GPU без OOM
- Сократить время обучения в ~4 раза (линейное ускорение от числа GPU)
- Запускать эксперименты на больших датасетах, которые ранее не помещались в память
